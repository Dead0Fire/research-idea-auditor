# 示例：评估“在约 2B 的 VLM 上使用免训练草稿策略加速”

> 这是一份**演示如何分析**的假设案例，不是查重结论或性能报告。具体相关论文、模型兼容性与实验结果必须另行核验。

## 当前判定

**缩小问题再验证（低信心）**。方向本身很广，尚不能把“免训练 + VLM + speculative decoding”宣称为新意。更值得检查的具体问题是：在视觉依赖度不同的任务中，低成本 draft 的接受率与额外验证开销如何变化，哪些条件下端到端加速反转？

## 现象 → 原因 → 方案

- **待证实的现象**：某些小型 VLM 的 decode 阶段仍占显著耗时，但真实任务包含视觉编码/prefill/短输出，纯 decode 加速不一定改善端到端延迟。
- **候选原因**：草稿生成/验证的额外成本超过减少 target 调用的收益；视觉细节依赖可能导致文本主导草稿接受率下降。
- **机制假设 H**：草稿策略的净收益受任务视觉依赖、输出长度、上下文长度与 verifier 成本共同决定，不能仅靠平均 acceptance rate 预测。
- **反例 C**：如果视觉编码和 prefill 已占绝大部分时间，即使 decode speedup 提高，端到端效果也可能微弱。

## 最小实验（示意）

1. 用同一 target、同一任务集和一致处理流程，测 target-only 的图像处理、prefill 和 decode 时延，先做 profile。
2. 在固定小样本上测一种无需更新参数的 draft，分别记录生成候选、验证、修正/回退、内存和输出长度。
3. 分层对比视觉依赖弱的描述类任务与需识别视觉细节的 OCR/问答类任务，控制 prompt 长度与图像设置。
4. 与已有优化 baseline、简单 n-gram/轻量 draft（若适用）比较，并测试去掉最关键策略的消融。
5. 分析结果：若只在长输出、弱视觉依赖工作负载中赢，应将贡献边界收紧；若全范围都无净收益，先区分草稿质量不足还是 verifier overhead 过大。

## 导师可能质疑

- 这相对已有无需训练的解码方法，有什么不可替代的新机制？
- 为什么选择这个目标设备与数据分布？可否推广？
- 你声称的是 exact 加速、近似质量-速度权衡，还是系统现象分析？实验能证明哪一个？

一张 *target-only 时延构成图* + 一张 *不同任务类别的 draft/verify 成本分解表* + 一个明确的下一步 go/no-go 判据。即使没有加速，也可以回答“瓶颈究竟在哪”。
