# 方法来源、整合与纠偏

本 Skill 从用户提供的科研经验文字中归纳一般方法，不复制原文长段落。原文中的个人百分比、主观会议分档、文献数量阈值以及关于科研贡献/某些模型机制的个别概括，均不作为事实依据。

## 主要借鉴的不同视角

- 用户先前提供的“把 idea 拆成可回答的小问题”的长文：真实问题、明确假设、最小验证、问题库、solo 组会。
- WYFhiahia（知乎：https://www.zhihu.com/question/506572911/answer/2274486846）：先广泛核查文献，再把想法细化为方案，并与导师交流；本 Skill 额外增加了调研停止条件和最小实验的并行推进机制。
- 盘图庚（知乎：https://www.zhihu.com/question/506572911/answer/1932736934033225114）：从现象、原因、影响因素到针对性方案的因果链；本 Skill 要求进一步给出可证伪预测和可排除替代解释的实验。
- 用户粘贴的其他知乎观点：成熟方案叙事、最接近工作定位、不应凭“无人做过”或简单指标改善定义贡献、先小项目练能力、保护探索、尊重严谨实验、可借助 AI 做前期草案但须核查。

## 必须纠正的常见推论

- “有人做过就算了”：不成立。新边界、新硬件、新任务条件、新机制认识、新实证结果可能仍有价值，但要明确独立差异。
- “看似简单却没人做，一定有大坑”：只能作为风险提示；可能是跨领域术语差异、成本变化、关注度不足、负结果未发表或需求新出现。
- “先想完整再动手”：应改为先想清关键假设和技术路径，不能靠思考区分的未知交给最小实验。
- “找到某数量的相关工作说明没有创新”：检索数量不能代替贡献对比。
- “导师支持=正确”：导师是强外部审查，但不是实验证据，也不能保证发表。
- “没训练就不算科研”：不成立。是否产生被验证的新知识才重要。
- “负结果=项目失败”：严谨的机制排查及清晰边界可能有科研价值，但需要足够系统且可复现。
- “AI 生成的可行性备忘录足以替代原文/实验”：不成立。AI 是假设整理工具而非独立事实来源。

## 文献引用责任

若分析具体论文，要独立检索正文与代码（有工具时），用原始论文支持每条关于方法、数字和创新性的断言；用户粘贴的论坛讨论只作为科研方法的启发，不应被混用为技术证据。
